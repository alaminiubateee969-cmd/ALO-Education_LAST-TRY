## Blockers for automatic deployment / live site

1. **Project dir is not a git repository.** `git remote -v` in
   `/home/aloedu/projects/learn-aloeducation` → `fatal: not a git repository`,
   and `package-lock.json` is missing there. It is an uploaded copy.
   → Run `scripts/bootstrap-vps.sh` once (moves the copy aside, clones,
   copies `.env`+`storage/`, rebuilds, health-checks; no migration).
2. **DNS does not resolve.** `https://learn.aloeducation.com/` from the VPS →
   `Could not resolve host`. No public live verification is possible until
   DNS (or the Cloudflare Tunnel ingress — `cloudflared` is listening locally)
   points the name at this host and a proxy vhost serves it.
3. **Proxy conflict to resolve.** Nginx owns 80/443; Caddy is stuck in
   `activating` with a valid config that includes
   `learn.aloeducation.com → localhost:3017`. Decide one proxy for the domain;
   the repo reference config is `deploy/nginx/learn-aloeducation.conf`.
   Diagnostics needed: `sudo nginx -T | grep -A15 'server_name'`,
   `cat /etc/caddy/Caddyfile`, `cat ~/.cloudflared/config.yml` (ingress),
   `getent hosts learn.aloeducation.com`.
4. **App port exposed.** 3017 listens on `0.0.0.0`, bypassing the proxy.
   `ecosystem.config.js` in this repo sets `HOSTNAME=127.0.0.1`; first deploy
   fixes the binding. Verify afterwards with `ss -lntp | grep 3017`.
5. **Bun is broken on this CPU.** `bun --version` → `Illegal instruction
   (core dumped)`. Never use Bun on this VPS; npm 10.9.9 is canonical
   (matches the decision to commit `package-lock.json`).
